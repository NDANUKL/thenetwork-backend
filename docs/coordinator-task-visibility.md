# Coordinator task visibility — 30 October 2026

Source changes only; deployment and device verification remain outstanding. The [production ownership policy](production-script-ownership.md) controls deployment.

Field Tasks exposes Project County as a list column and standard filter. Existing allocations already carry project county through native project alignment. Saved personal list layouts may need the column selected in List Settings. Field Request previews include the field brief, title and county; request list links show the field brief on hover. Field Task request links show the allocation's pinned objective on hover.

County Assignment Balance is available from the Field Task list and individual Field Task/Field Request forms. It lists allocations with project county, scout name, current scout base county, status and server start time, with assignment-date and project/county filters. The chart counts allocations by scout county, excluding cancelled tasks. Repeated allocations count separately; this is not unique-scout headcount or an automatic fairness quota. Profile county edits affect historical report grouping. Frappe document permissions apply to both tasks and scout profiles.

New Scout Application inserts queue one email to enabled System Users with the Field Operations Coordinator role. This uses the standard Frappe outgoing Email Account, Email Queue and scheduler; DD Access Settings/Resend is not its transport. Configure and verify the outgoing account, recipient roles and worker delivery on staging. No historical applications are emailed by migration, and approval/editing does not enqueue a new-application alert.

Mobile Task Brief activity previously stayed local until submission, leaving Desk Assigned despite ongoing work. The coordinated mobile change reports saved arrival, answers, access issues, observations or captures on sync. The new authenticated endpoint checks assignment ownership and brief hash, serializes updates and advances Assigned → Accepted → In Progress through the native controller. Retries never reopen or regress terminal tasks. Opening a brief alone does not start it. Accepted is transitional, not a separate explicit scout acceptance step. Started At records server receipt, not an independently verified offline start time.

Submitted remains server-accepted submission; Approved remains coordinator approval. Offline/queued work cannot be observed in Desk until a successful sync. Clarification/additional-evidence outcomes remain governed by submission review. Deploy the backend before the matching mobile release; run the read-only cutover inventory before deployment, normal migration/build, and verify list previews, report permissions, queued email delivery and online/offline/reconnect progress on a real device. Local tests do not establish production delivery.

Status-filter follow-up: the Field Task list's main dropdown excludes Accepted (an internal transition, with no explicit current mobile acceptance action) and the internal Cancelled state. Rejected filters cancelled allocations whose recorded review outcome is Reject; other cancelled records display their closure outcome or Ended. The obsolete Awaiting authorization status is removed from current choices; legacy rows remain historical and are not migrated by this source change. Corrections filters In Progress allocations with Correct answers rework, and the list indicator displays Corrections. Submitted corrections no longer match Corrections.

Status-storage follow-up (31 October): `Cancelled` is removed from the Field Task DocType options and task status is read-only in Desk; all status changes remain server-owned. New submission rejections and reassigned-away allocations use `Rejected`, with review outcome distinguishing a rejection from a reassignment. Existing `Cancelled` rows are not migrated and remain supported by compatibility readers in Desk and mobile. They can be viewed as ended history, but because `Cancelled` is no longer a valid Select option, editing and saving those legacy rows may require a later data migration. Other DocTypes retain their own unrelated `Cancelled` states.

The Field Task list has no Closed or Cancelled status filter. Rejected selects actual rejected submissions and legacy cancelled rows whose review outcome was Reject. Other ended allocations display their outcome or Ended. No existing task data was migrated by this source change.

The content includes applicant name, county and authenticated Desk review link. Dynamic values are HTML-escaped. Recipients and transactional Email Queue delivery are unchanged. Requires backend deployment; no live notification was sent during development.

Application IDs are omitted from the email subject and visible body. The review button still links to the application, and internal queue references retain its ID.

Full sync includes these historical task IDs in authoritative membership; delta sync applies the same modified-time cursor. Approval, old evidence, original snapshots and pins are not changed.
