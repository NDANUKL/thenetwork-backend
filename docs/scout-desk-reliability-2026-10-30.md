# Scout progress and Desk corrections ? 30 October 2026

Local source changes; not a claim of production deployment. Follow production-script-ownership.md and the normal native deployment process. No retired scripts, existing applications, task pins or historical submissions were rewritten.

- Mobile now persists a per-draft progress acknowledgement only after the server confirms In Progress and a start timestamp. Local In Progress is not proof of server receipt. Existing drafts without the marker retry on sync; subsequent autosaves preserve the marker. Concurrent edits are not replaced by the acknowledgement. Queued work also acknowledges activity before uploading. The foreground scheduler includes unacknowledged In Progress tasks and correctly recognizes text access-issue reasons.
- `record_progress` keeps existing ownership, brief-hash and row-lock checks. It repairs a missing started_at on an open In Progress task using current server time, once. Closed tasks remain closed and historical offline times are not guessed. Normal transitions still run Field Task hooks, updating project status and scout workload. County Assignment Balance directly reads Field Task.status and started_at; refresh it after the scout's successful sync. Offline work cannot appear on Frappe before it reaches the server.
- Scout Application offers Reactivate only for a deactivated linked scout and authorized reviewers. It calls the existing audited reactivation API, requires a reason and reloads the application. Rejected/pending applications cannot use this to bypass approval.
- Reviewed By is rendered with the linked reviewer's User.full_name loaded on the server, rather than the applicant's full_name used by Frappe's generic User-link formatter. The stored reviewer and destination are unchanged.
- Field Request subjects use plain request-number text in Frappe's existing link, with project_title as a safely assigned hover attribute. Returning an anchor string as subject text caused visible escaped HTML.
- Diaspora Request submission_id remains required and unique, stored and accessible on the document. It is no longer a default list column; list setup also removes it from existing customized table layouts without deleting saved data.
