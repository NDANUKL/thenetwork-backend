# Project questionnaire editing and report preparation

The coordinator prepares the questionnaire before dispatch. The Scout checklist starts from a shared service template. On that project only, the coordinator can edit question wording and instructions, add custom questions, remove irrelevant service rows, and specify required photos, videos or documents and their capture subjects. Required site/access controls, service authorization and protected mandatory evidence cannot be removed. Protected evidence wording can be adapted to the request.

Use Add Row for a new question and Edit question and evidence to configure it. New questions support written answers, single choice and multiple choice. A template row retains its established response format; replace it with a custom row to use different choices. Complex assigned items remain configurable through Configure selected checks. Source templates and published questions are not edited by this workflow.

Save the edits, then tick Checklist reviewed. Confirm questionnaire is a shortcut that saves and confirms the current saved version. Text, order, evidence, configuration and relevant scope/context edits invalidate confirmation. The confirmation endpoint checks the saved modification timestamp so a coordinator cannot inadvertently confirm somebody else's newer edit. The reviewer and timestamp are recorded.

On dispatch, customized questions are materialized as a project-specific, immutable FP Questionnaire/FP Question version. Its ID is content-addressed and repeated dispatch of the same content reuses it. Different project edits produce a new version. Shared templates remain unchanged, cannot pick up project versions through service lookup, and existing tasks retain their original questionnaire IDs and snapshots. Selected unmodified template questions continue through the existing versioned dispatch path.

Customized dispatches use the compatible v2 question engine and verified-visit workflow. This also allows projects initially loaded from older service templates to use custom questions without modifying historical v1 tasks. Enable the existing questionnaire/verified-visit feature flags and release the compatible app before dispatching customized work. The app advertises questionnaire_editor_version=1; older clients receive an update-required error for these assignments.

For custom project questionnaires the scout records whether each service finding was directly observed, obtained from a representative, read from a record, or based on a combination. Non-observation sources require a role/reference. The same rule is validated offline and on the backend. This supports factual report source labels without guessing provenance from silence. The coordinator's submission review displays that basis and assigned instructions.

The exact assigned questions define the review and report. After the required submissions pass, automatic report preparation populates each service question's heading, approved answer, source basis, evidence references and limitations. Missing answers stay explicitly Not verified. Shared arrival/access controls supply visit context; optional additional observations are included when answered. There is no separate customer-question mapping or post-submission request-to-question review. Existing mapping metadata is retained as hidden historical data, but is not required for dispatch or new report drafts. Existing draft reports can be refreshed from approved findings. Approved reports remain locked.

Revisit commercial authorization, same-scout/replacement-scout controls, payment rules and customer report release are unchanged by this work. No AI generation has been added.

## Rollout and acceptance

Run normal Frappe migration for the edited checklist fields, confirmation metadata and project-version ownership links, then build Desk assets and deploy the compatible scout app. Verify a maize request by removing boundary checks, adapting the required visit-evidence question, adding harvest-status choices and photographs, confirming, assigning, answering on the app, reviewing and approving. Confirm that the generated report uses those same words and answers without any mapping table. Repeat after modifying the project and confirm the first task is unchanged. Verify legacy unedited tasks, rework/revisit authorization, required media, declined access, source attribution, concurrent edits and private evidence release. Local mocks/SQLite checks do not replace a real Frappe model-sync and device acceptance pass.
