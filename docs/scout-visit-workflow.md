# Scout visit workflow policy

New assignments use immutable template version 3, questionnaire protocol 2 and visit workflow version 2. Existing assignments and offline drafts keep their pinned workflow.

Before arrival, show the task brief and a short list of assigned checks/evidence. Before unlocking answers or capture, verify arrival using the actual assigned site radius and GPS accuracy. The legacy temporary testing radius must not apply. An unsuccessful check can be retried or sent through an arrival-exception review route; this route cannot contain questionnaire answers/media and does not establish verified arrival or completed fieldwork.

After verified arrival, keep Checks, Capture evidence and Complete findings available independently. Checks offer quick outcomes/notes, with reminders to record exact references, quantities, readings and institutional responses before leaving. Evidence can be captured together against a task-specific shot list without answering each question first. Before switching to later write-up, show remaining essential details and evidence. Written findings, captions and submission can be completed from elsewhere without refreshing or replacing the saved arrival.

Visual land/property/construction/business/vehicle/equipment/delivery services require specified photos and an overview video. A file can satisfy several appropriate requirements. Registry/institution services use approved written, authorised-photo or verbal confirmation; generic footage does not establish issuer confirmation. Custom and survey capture must have explicit permitted subjects. Prohibited, refused, inaccessible or unsafe capture is recorded as unfulfilled evidence for coordinator review.

Use an in-app camera for the new workflow. Sample foreground GPS immediately before the photo shutter or video recording starts, and retain the sample time, capture time and accuracy separately. No continuous/background tracking is needed. Indoor/missing/off-site capture locations require an explained review submission, not automatic rejection of the file. Imported documents have import provenance and no invented capture GPS/time.

Generate editable captions from the assigned subject/item. Reusing a file requires selecting the checks it supports, not typing another caption. Require extra description only for unclear subjects or issues that are not already described in the linked finding. Preserve capture metadata when captions, links or findings are edited later. Client-facing captions remain coordinator-reviewable.

No production handover, script retirement or automatic upgrade of assigned work is authorised by these source changes. Activate only after backend staging/model sync, compatible mobile rollout and physical-phone GPS/camera/offline acceptance.
