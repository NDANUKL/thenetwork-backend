# Beta feedback (source only)

Deploy the native DD Beta Feedback DocType and beta_feedback module with an ordinary schema migration, then deploy the compatible website. The existing dashboard sync must run to update the Field Operations Custom HTML Block; use the normal migration path, never retired scripts. Verify the shortcut appears after migration.

The website displays the invitation on dashboard Home and on individual request and inquiry pages. Both record types are owned Diaspora Requests. A verified, approved customer with at least one such record can submit up to two responses per account, including any historical response. Direct access and POST requests are subject to the same server eligibility check. Identity comes from the authenticated website session through the existing System Manager bridge; backend fields never trust browser-provided names, email, timestamps or account IDs.

DD Beta Feedback stores form version 1, all 12 questions, conditional confusion details, use case, fair amount and currency, customer account/name/email and server submission time explicitly in UTC. Form data is immutable. Field Operations Coordinators and System Managers have read/report/export access; customers cannot list responses through Desk or submit directly through Frappe. Concurrent POSTs serialize on the account and read the current response count under that lock. Retries for a saved slot return success without overwriting or consuming the next slot. Schema sync replaces the unique customer-account index with a regular index. Confirm the index change on staging before deploying the website. Records cannot be manually deleted to reopen eligibility.

Staging acceptance: customer with no request cannot submit; request and inquiry owners see the invitation on Home and their detail pages; all answer types and conditional fields validate; retry after a lost response creates no duplicate; two concurrent submissions for the same slot store one response; Home still offers feedback after the first response; reaching two hides the invitation on Home and detail pages; a second customer cannot read another response; a coordinator can open the shortcut and see all questions, answers, identity and UTC timestamp. Validate desktop/mobile keyboard layout and real website-to-backend session integration. No source-only check establishes deployment.
